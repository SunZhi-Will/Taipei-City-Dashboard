# HMR 熱更新修正 / HMR Hot Reload Fix

## 2026-04-17 15:52

- objective:
  - 修正前端在 Docker + Nginx 開發環境下未正常熱更新（HMR）問題。

- files:
  - Taipei-City-Dashboard-FE/vite.config.js

- summary:
  - 補齊 Vite 的 `server.watch` polling 設定，避免 Windows/WSL bind mount 事件遺失。
  - 補齊 Vite 的 `server.hmr` 設定，固定走 `ws://localhost:80`，提升經由 nginx 代理時的 HMR 連線穩定度。
  - 重啟 `dashboard-fe` 容器使設定生效。

- change-type:
  - Fixed

- technical-details:
  - 在 Docker Compose 模式下新增：
  - `watch.usePolling = true`
  - `watch.interval = Number(process?.env.CHOKIDAR_INTERVAL || 300)`
  - `hmr.protocol = "ws"`
  - `hmr.host = "localhost"`
  - `hmr.clientPort = 80`

- verification:
  - 指令：`docker compose restart dashboard-fe`
  - 日誌確認：Vite 顯示 `vite.config.js changed, restarting server...` 與 `server restarted.`
  - 日誌確認：Vite 啟動成功並輸出 `Local: http://localhost:80/`

- performance-impact:
  - 啟用 polling 會增加少量檔案監聽開銷，但可顯著提升跨平台 mount 的變更偵測穩定性。

- impact-risk:
  - 影響範圍僅前端開發模式熱更新；不影響 production build。
  - 若使用非 localhost 網域開發，可能需再調整 `hmr.host/clientPort`。

- regression-test:
  - 修改任一前端檔案（例如 `src/components/...`）後確認瀏覽器自動更新。
  - 驗證透過 `http://localhost` 進入時，HMR websocket 可建立。

- traceability:
  - N/A

- next-actions:
  - 檢查瀏覽器是否從 `http://localhost` 進入（避免走其他 host/port 導致 HMR host 不一致）。
